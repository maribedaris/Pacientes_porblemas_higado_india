# Data structure

## Fuente del proyecto

El dataset utilizado en este proyecto es un dataset público modificado por el profesor y descargado en local. La fuente efectiva y única de datos es `data/01_raw/Pacientes_porblemas_higado_india.csv`; los notebooks y procesos deben leer siempre desde esta ruta y no desde una fuente externa.

## Layered data-engineering convention

![layered data engineering](https://docs.kedro.org/en/stable/_images/data_layers.png)

| `Folder in data`  | `Description`                                                                                                                                                                                                                                                                                                                                                           |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `01_raw`          | Initial start of the pipeline, containing the sourced data model(s) that should never be changed. It forms your single source of truth to work from. These data models are typically un-typed in most cases, e.g. CSV, but this will vary from case to case.                                                                                                            |
| `02_intermediate` | Optional data model(s), which are introduced to type your raw data model(s), e.g. converting string-based values into their current typed representation.                                                                                                                                                                                                               |
| `03_primary`      | Domain-specific data model(s) containing cleansed, transformed and wrangled data from either raw or intermediate, which forms your layer that you input into your feature engineering.                                                                                                                                                                                  |
| `04_feature`      | Analytics-specific data model(s) containing a set of features defined against the primary data, which are grouped by feature area of analysis and stored against a common dimension.                                                                                                                                                                                    |
| `05_model_input`  | Analytics-specific data model(s) containing all feature data against a common dimension and, in the case of live projects, against an analytics run date to ensure that you track the historical changes of the features over time.                                                                                                                                     |
| `06_models`       | Stored, serialised pre-trained machine learning models.                                                                                                                                                                                                                                                                                                                 |
| `07_model_output` | Analytics-specific data model(s) containing the results generated by the model based on the model input data.                                                                                                                                                                                                                                                           |
| `08_reporting`    | Reporting data model(s) that are used to combine a set of primary, feature, model input and model output data used to drive the dashboard and the views constructed. It encapsulates and removes the need to define any blending or joining of data, improves performance, and allows replacement of the presentation layer without having to redefine the data models. |
